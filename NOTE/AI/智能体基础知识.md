## 一、MCP 与"上下文"：为什么总一起出现？

| | MCP | 上下文(Context)|
|:-:|:----|:---------------|
| **本质** | 协议（规定怎么连接）| 数据（当前有什么信息）|
| **管什么** | 智能体怎么调用外部工具/数据源 | 用户历史、思考步骤、检索到的文档 |
| **类比** | USB接口标准（怎么插、怎么传）| 你正在处理的文档内容（存在内存里）|

> 💡 **一句话**：MCP是智能体的"管道规范"，上下文是智能体的"信息总和"。一个管连接，一个管内容，缺一不可。

## 二、智能体开发比大模型应用难在哪？

### 结论：难在三个维度

| 维度 | 大模型应用 | 智能体 | 难点 |
|:-----|:-----------|:-------|:-----|
| 任务类型 | 单次推理（输入→输出）| 多步规划+执行+调整 | 要自己决定"下一步干什么" |
| 不确定性 | 低（prompt稳定就可控）| 高（工具可能失败、环境变化）| 必须处理异常/重试/换方案 |
| 调试难度 | 看最终输出就行 | 追踪思考链+工具调用链 | 错误藏在中间某步 |

🌰 大模型应用=专家直接回答；智能体=专家自己查资料、打电话、做实验、写报告——中间任何环节出错都要自己纠正。

### 核心原理：ReAct 循环

智能体 = 把大模型放进一个循环：

```
Thought(思考) → Action(执行工具) → Observation(看结果) → 回到 Thought
     ↑                                                        │
     └────────────────────────────────────────────────────────┘
                    不断重复直到目标达成
```

这个模式叫 **ReAct（Reason + Act）**。

### 四大核心模块

| 模块 | 干什么 | 技术手段 |
|:-----:|:-------|:---------|
| **规划** | 把大目标拆成子任务 | 思维链(CoT)、任务分解 |
| **记忆** | 记住历史和中间结果 | 向量数据库、短期缓存 |
| **工具调用** | 操作外部API/文件/浏览器 | Function Calling、MCP |
| **反思** | 检查结果修正计划 | 自我批评、外部验证器 |

## 三、从零搭建一个智能体（代码版）

### 最小可运行示例（DeepSeek API）

```python
import requests, json

# 1️⃣ 定义工具
def get_weather(city):
    return f"{city} 今天晴天，25℃"

# 2️⃣ 工具描述（告诉AI有哪些工具可用）
tools = [{"name": "get_weather", "description": "查天气", "parameters": {"city": "str"}}]

# 3️⃣ ReAct 主循环
def deepseek_agent(goal):
    messages = [{"role": "user", "content": goal}]

    while True:
        # 调用大模型
        resp = requests.post(
            "https://api.deepseek.com/v1/chat/completions",
            headers={"Authorization": "Bearer YOUR_API_KEY"},
            json={"model": "deepseek-chat", "messages": messages}
        )
        reply = resp.json()["choices"][0]["message"]["content"]

        # 判断是否要调工具
        if '{"tool":' in reply:
            call = json.loads(reply[reply.find('{'):reply.rfind('}')+1])
            if call["tool"] == "get_weather":
                result = get_weather(call["args"]["city"])
                # 把工具结果喂回给模型
                messages.append({"role": "assistant", "content": reply})
                messages.append({"role": "user", "content": f"工具返回：{result}"})
        else:
            print("最终回答：", reply)
            break   # 不需要调工具了 → 结束循环

deepseek_agent("北京天气怎么样？")
```

**关键点**：
- `while True` 就是 ReAct 循环 —— 模型决定调工具就继续，直接回答就 break
- 工具返回的结果要**塞回 messages**，让模型基于新信息继续思考
- `def` = Python定义函数的关键字（define的缩写），把代码打包成可复用的功能块

## 四、Dify 常用术语速查

### HTTP 请求基础

| 术语 | 大白话 | 例子 |
|:-----:|:-------|:-----|
| URL | 网址 | `https://api.weather.com/v1/beijing` |
| GET | 获取数据（只看不改）| 打开链接看内容 |
| POST | 发送数据（提交操作）| 填表单并提交 |
| HEADERS | 身份证/格式说明 | `Authorization: Bearer xxx` |
| PARAMS | 挂URL后面的参数 | `?city=beijing&days=3` |
| BODY | 请求体里的实际数据（JSON）| `{"model": "gpt-4", ...}` |

### 流程类型

| 类型 | 特点 | 用途 |
|:-----:|:------|:-----|
| **Chatflow（对话流）** | 有记忆的多轮交互 | 客服、聊天机器人 |
| **Workflow（工作流）** | 固定步骤，一套做完结束 | 每日报表、数据处理 |
| **HTTP请求节点** | 在流程中调用外部API | 查天气、发邮件、查数据库 |

> 💡 **记忆口诀**：Chatflow="你来我往"的对话；Workflow="一套做完就收工"的任务。`TOPK`=检索时只取最相关的K条结果（减少噪声）。
