## 一、核心概念辨析（最容易混的5个词）

### LLM vs Agent vs Workflow vs MCP vs Prompt

| 概念 | 是什么 | 类比 | 关键区别 |
|:-----:|:-------|:-----:|:---------|
| **LLM** | 大语言模型 | 百科全书 | 只回答，不行动 |
| **Agent** | 智能体 | 员工 | 能自主决策+调用工具 |
| **Workflow** | 工作流 | 火车轨道 | 固定步骤，不变通 |
| **MCP** | 模型上下文协议 | USB-C接口 | AI连接外部工具的统一标准 |
| **Prompt** | 提示词 | 提问的艺术 | 你跟AI说的话 |

> **LLM是大脑，Agent给大脑配上手脚，Workflow是钉死的流程，MCP是万能插座，Prompt是你怎么说话。**

**Agent vs Workflow 怎么选？**

| 维度 | Agent（智能体）| Workflow（工作流）|
|:-----|:---------------|:------------------|
| 谁做决定？ | AI自己规划 | 人事先设定 |
| 步骤可变？ | 动态调整 | 固定不变 |
| 遇到意外？ | 自主重试换方案 | 走预设分支或失败 |
| 适合场景 | 复杂/不确定任务 | 稳定/高频/确定性任务 |
| 例子 | 自动订票（航班变动时换方案）| 每日定时发报表 |

> 实际系统常两者混合：**工作流做骨架，Agent做灵活节点**。

## 二、模型架构演进：从排队到开会

```
RNN(排队) → LSTM(带笔记排队) → Transformer(并行开会)
 串行慢        记忆稍强           并行快 + 全局理解
```

### RNN —— 一个个字排队读

- 一个字一个字处理，**串行**，训练慢
- 读到后面忘了前面（长距离依赖差）
- 🌰 一个人搬砖，一次搬一块，100块跑100趟

### LSTM —— 排队但带了笔记本

- 加了"遗忘门/输入门/输出门"，有选择地记/忘
- 能记住几百个字了，但还是**串行**
- 🌰 带纸笔搬砖，但还是一块一块来

### Transformer（2017 Google）—— 彻底革命

**核心：自注意力机制** —— 每个词同时看所有词，算彼此关联度。

| 组件 | 干什么 |
|:-----|:-------|
| **自注意力** | 每个词问所有人："你对我重要吗？" |
| **多头注意力** | 多视角同时看（语法、语义、指代）|
| **位置编码** | 并行处理必须告诉模型词的顺序 |

优势：**并行计算（GPU喜欢）+ 长距离依赖不再是问题**

局限：O(L²)复杂度，超长文本（整本书）会爆。后来有了稀疏注意力等改进。

> 💡 **记忆点**：Transformer = 抛弃排队，全场开会 → 又快又能看全局。

## 三、Encoder vs Decoder（最容易搞混）

### 先搞清两对概念

| | **模块（名词）** | **动作（动词）** |
|:-:|:-----------------|:-----------------|
| **Encoder** | Transformer左边的结构 | 把输入变成内部向量 |
| **Decoder** | Transformer右边的结构 | 把向量变成输出 |

💡 **口诀**：模块是工具，动作是功能。有工具方便，没工具也能干。

### 三种变体

| 架构 | 代表 | 特点 | 类比 |
|:-----:|:----:|:-----|:-----|
| **Enc + Dec** | 原始Transformer（翻译）| 编码器读懂→解码器生成 | 读英文→写中文摘要 |
| **仅Decoder** | GPT系列 | 用自注意力完成"编码"，续写任务 | 老师给开头，你接着写 |
| **仅Encoder** | BERT | 双向理解，加分类头输出标签 | 听完就判断，不说话 |

**常见疑问**：

| 问题 | 答案 |
|:-----|:-----|
| GPT没编码器怎么理解输入？ | 解码器的自注意力能看到前面所有词，本身就完成了"编码" |
| BERT没解码器怎么输出？ | 加一个分类头（softmax）把向量解码成标签 |
| 为什么不给GPT加编码器？ | 没必要，续写任务不需要，加了反而破坏自回归性质 |

## 四、评价AI：几个关键指标

| 指标 | 是什么 | 看什么 |
|:-----:|:-------|:-------|
| **平均值(Mean)** | 所有结果的平均 | 整体水平 |
| **期望(Expectation)** | 结果×概率的和 | 长期理论回报 |
| **方差(Variance)** | 数据偏离均值的程度 | 稳定性 |

> 💡 **口诀**：平均值看水平，方差看稳定，两者一起看才完整。
>
> 例：模型A输出[9,9,9,9,9]均值9方差0→极其稳定；模型B[10,10,10,0,0]均值6方差大→忽高忽低。

## 五、嵌入式AI：声音怎么被听见的？

**信号链5步**：

```
声波 → 麦克风(模拟信号) → ADC(数字化) → 预处理(提取特征) → TinyCNN推理 → 执行(GPIO控制)
```

| 步骤 | 说明 |
|:-----|:-----|
| **麦克风** | 声音振动空气→电压波动 |
| **ADC** | 电压→数字（采样率16kHz=每秒16000次）|
| **预处理** | 切成20-40ms小段，提取MFCC/梅尔谱 |
| **TinyCNN** | 几KB~几百KB的小网络，跑在单片机上 |
| **执行** | MCU控制GPIO，点亮LED/继电器 |

常用硬件：ESP32、STM32F4、K210、RP2040

> 🌰 麦克风是耳朵，ADC是把声音写成数字，预处理是去噪+提取特征，TinyCNN是判断你说啥的小脑。

## 六、RAG vs GraphRAG：让AI查资料更聪明

| | 普通 RAG | GraphRAG |
|:-:|:---------|:---------|
| **做法** | 文档切段→向量化→找相似段落→喂给LLM | 抽实体+关系→构建知识图谱→找相关子图→喂给LLM |
| **找什么** | 字面相似的段落 | 相关实体和路径 |
| **优点** | 简单快速 | 能多跳推理 |
| **缺点** | 无法跨段落推理 | 构建成本高（需额外NLP模型）|

> 🌰 问"A和B公司什么关系？"——普通RAG找不到同时提两者的段落就哑火；GraphRAG能沿图谱路径 A→投资→B 找到答案。

## 七、蒸馏模型：老师教学生

**做法**：用大模型（教师）的"软输出"（概率分布）当额外信号，训练小模型（学生）。

| | 教师（大模型）| 学生（小模型）|
|:-:|:-------------|:-------------|
| 参数量 | 几十亿~万亿 | 教师的1/10~1/100 |
| 训练成本 | 几百万美元（一次性）| 少量成本 |
| 推理成本 | 高 | **低（省在这里！）** |
| 适用 | 训练/研究 | 大规模部署（每天上亿次调用）|

🌰 **类比**：老师花多年成长为专家 → 学生花钱上一门专精课 → 学生在这门课上接近老师水平。

> ⚠️ **常见误区**：DeepSeek是大模型（671B参数），不是蒸馏出来的"小模型"。它可能用了蒸馏技巧，但本质是大模型。

## 八、硬件：CPU / GPU / NPU / 核显 / 独显

| 名称 | 全称 | 擅长 | 特点 | 类比 |
|:-----:|:-----|:-----|:-----|:-----|
| **CPU** | Central Processing Unit | 复杂逻辑、串行任务 | 几十个强核心 | 数学教授 |
| **GPU** | Graphics Processing Unit | 大规模并行（矩阵运算）| 几千个弱核心 | 一万小学生同时做加法 |
| **NPU** | Neural Processing Unit | 边缘AI推理 | 超低功耗（毫瓦级）| 专用切菜刀 |
| **核显** | 集成显卡 | 日常图形、轻量计算 | 共用内存、省电便宜 | 够用就行 |
| **独显** | 独立显卡 | 3A游戏/AI训练渲染 | 独立显存、可升级 | 性能怪兽 |

> 💡 **记忆点**：CPU是教授，GPU是小学生军团，NPU是专用切菜刀。AI训练主要靠GPU，手机AI靠NPU。

> **核显≠CPU**：有些CPU内部集成了GPU（叫核显）。把GPU做成独立插卡就是独显。

## 总结速查卡

```
概念层：LLM < Agent（LLM+执行器+目标）< Workflow（固定流程）
架构层：RNN < LSTM < Transformer（自注意力+并行）
变体层：GPT(仅Dec) / BERT(仅Enc) / 原始(Enc+Dec)
部署层：蒸馏(大教小) / RAG(查资料) / 嵌入式(TinyCNN+MCU)
硬件层：CPU(逻辑) / GPU(并行训练) / NPU(边缘推理)
```
